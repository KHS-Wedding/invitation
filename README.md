# 모바일 청첩장 v24

현재 디자인과 Vanilla JavaScript 갤러리를 유지하는 GitHub Pages 정적 청첩장입니다.

## 내용 수정과 미리보기

1. `wedding_config.py`에서 문구, 날짜, 장소, 교통, 계좌를 수정합니다.
2. `photos/cover`에 대표사진 한 장, `photos/gallery`에 순서대로 사진을 넣습니다.
3. `python -m pip install -r requirements.txt`를 실행한 뒤 `python manage.py preview`로 확인합니다.
4. `python manage.py build`를 실행하면 `dist`에 배포용 파일이 생성됩니다.

갤러리는 파일명 자연순으로 배치합니다. 전체 사진은 긴 변 1280px·품질 72, 썸네일은 긴 변 480px·품질 68의 WebP로 생성하며 비율을 유지합니다. 스마트폰 JPG 안의 MPO 보조 프레임은 대표 정지 이미지로 처리합니다. 커버는 긴 변 1600px입니다.

## v24 안정성 개선

- MPO를 움직이는 이미지로 오인해 원본을 썸네일에도 복사하던 문제 수정
- 사진 내용 해시 파일명 및 설정/정적 파일 해시 버전으로 캐시 갱신
- 첫 화면 커버 우선 로딩, 갤러리 썸네일은 화면 근처에서 로딩
- 전체 사진 준비 실패 시 썸네일 유지, 재시도 및 지연 안내
- 하단 점 영역의 즉시 연속 선택은 유지하고 드래그 종료 시 전체 사진 준비
- 앞뒤 사진 사전 로딩 유지, 닫기/재열기 때 이전 전환 작업 취소
- 사진 중앙 표시, 원래 비율, contain, 좌우 스와이프와 손가락 추종 유지
- 복사 실패 판정 및 직접 복사 대체 화면
- 데이터 로딩 실패에도 정적 예식 안내 표시
- 모달 포커스 제한/복귀, 계좌 펼침 상태, 동작 감소 설정 보완
- 한국 날짜 기준 D-day 및 예식 후 문구
- GA4의 계좌/주소 복사 결과, 더보기, 예식장 전화 이벤트

현재 예식 정보는 `wedding_config.py`를 기준으로 합니다. 신부 측 예시 계좌는 `show: False`로 숨겨져 있습니다. 실제 계좌번호로 수정한 뒤 True로 바꾸면 다시 표시됩니다. 신랑 측 계좌와 기존 복사 방식은 유지합니다.

## 배포

GitHub Pages 설정의 Source는 GitHub Actions를 사용합니다. `main`에 변경을 올리면 회귀 검사, 빌드, 산출물 검증 후 Pages로 배포합니다. 별도 서버는 필요하지 않습니다.

`dist`와 Python 캐시는 저장소에서 추적하지 않습니다. 배포 원본은 `manage.py`, 설정, `templates`, `static`, `photos`입니다. 빌드 검증은 파일 누락, 미완성 HTML, 이미지 읽기 및 WebP 크기를 검사하고 갤러리 용량을 출력합니다. 원본 대체 경고가 있으면 원인을 확인하세요.

회귀 검사: `python -B -m unittest discover -s tests -v`

## 배포 전 확인

- 예식 일시, 장소, 계좌의 실제 정보를 확인합니다.
- iPhone Safari와 Android Chrome에서 사진 중앙 표시, 스와이프, 하단 끝까지 드래그를 확인합니다.
- 빠른 닫기/재열기, 이미지 요청 실패, 주소/계좌/URL 복사를 확인합니다.
- 네이버·카카오 링크의 실제 목적지를 확인합니다.
- 공유 미리보기 사진을 변경하면 `site.share_image`도 새 파일명으로 갱신합니다.

원본 사진은 공개 저장소에 포함되어 있습니다. 배포 WebP는 EXIF를 전달하지 않지만 원본 자체와 저장소 이력의 공개 범위는 별도로 관리해야 합니다.
